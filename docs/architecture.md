ОБЩАЯ КОНЦЕПЦИЯ:
Решение построено по принципу модульной клиент-серверной архитектуры с четким разделением
ответственности между четырьмя слоями: клиентское приложение (Frontend),
сервер бизнес-логики (Backend), хранилище данных (Database) и внешний
сервис искусственного интеллекта (AI Module).

СТЕК ТЕХНОЛОГИЙ:
Frontend: Vite, Vanilla JavaScript, Phaser 4 (игровой движок), HTML5/CSS3
Backend: Python 3.10+, Django, Django REST Framework
База данных: SQLite (локальная разработка) / PostgreSQL (продакшен)
AI-модуль: дообученная нами vLLM (OpenAI-compatible API)
Аутентификация: JWT (JSON Web Token)

КОМПОНЕНТЫ СИСТЕМЫ:
Клиентский слой (Frontend) отвечает за рендеринг игрового мира через движок Phaser, отображение UI-элементов (меню, профиль, чат) 
через HTML-оверлеи поверх игрового canvas, загрузку конфигураций уровней из JSON-файлов и взаимодействие с Backend через REST API.

Серверный слой (Backend) управляет аутентификацией пользователей через JWT, хранит профили проводников и их прогресс, обрабатывает игровые сценарии,
проксирует запросы к LLM-модели с обогащением контекста (архетип пассажира, параметры сцены) и реализует механизм Fallback при недоступности ИИ.
Также отвечает за геймификацию: начисление XP, разблокировку достижений, таблицу лидеров.

Слой хранения данных содержит синтетические профили пользователей, историю сессий, справочник достижений и
конфигурации сценариев. Все данные анонимизированы в соответствии с 152-ФЗ.
AI-модуль выполняет генерацию диалогов в реальном времени на основе переданного контекста и
возвращает текстовую реакцию NPC вместе с числовыми изменениями игровых шкал (loyalty_change, safety_change).

ПОТОК ДАННЫХ ПРИ ИГРОВОЙ СЕССИИ:
Игрок запускает сессию → Frontend загружает JSON-конфигурацию вагона (координаты сидений, параметры геймплея) ->
На случайных сиденьях генерируются NPC со случайными архетипами -> Игрок перемещается по вагону (WASD) ->
При приближении к NPC (<100px) появляется подсказка [E] -> Нажатие E открывает HTML-чат ->
Сообщение игрока отправляется на POST /api/ai/chat/ -> Backend формирует промпт с контекстом архетипа ->
LLM возвращает ответ и изменения шкал -> Frontend обновляет UI в реальном времени ->
По истечении таймера сессия завершается -> Начисляется XP, обновляется профиль, показывается дебрифинг.

КЛЮЧЕВЫЕ ЭЛЕМЕНТЫ РЕШЕНИЯ:
Создание ИИ-движка на основе дообученной нами LLM модели, которая выдает МАКСИМАЛЬНО гибкие и живые ответы и
лучше всего понимает какие ситуации нужно создать конкретному бортпроводнику для улучшения конкретных навыков
общения и решения нестандартных ситуаций, то есть улучшения так называемых soft skills.

Разделение функций ИИ движка на ответы на вопросы от лица NPC и
анализ всего диалога для последующего создания персональных советов бортпроводнику.
